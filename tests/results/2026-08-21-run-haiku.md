# Behavioral Test Run — All 12 Scenarios on Claude Haiku 4.5 — 2026-08-21

Follow-up to three prior runs, all on Claude Sonnet 5
([`2026-08-21-run.md`](./2026-08-21-run.md),
[`2026-08-21-run-cfh.md`](./2026-08-21-run-cfh.md),
[`2026-08-21-run-ijkl.md`](./2026-08-21-run-ijkl.md)). Those runs found
all 12 scenarios in `tests/scenarios.md` (A-L) passed under both
with-skill and baseline conditions — including four scenarios (I-L)
specifically engineered with authority pressure and more tempting wrong
answers. The consistent recommendation across those runs was to test a
weaker model, on the reasoning that a model with less inherent epistemic
caution would be more likely to actually fail some scenarios under
baseline, producing a real pass/fail delta the skill could then close.

This run re-executes all 12 scenarios (24 runs: with-skill vs. baseline
per scenario) on **Claude Haiku 4.5** — the smallest/fastest model
available in this environment — using the identical prompts from the
three prior Sonnet 5 runs.

## Interpretation

**24/24 pass, including all 4 adversarial scenarios (I-L), on the smallest
model available in this environment.** This is a stronger and more
surprising result than the hypothesis going into this run predicted — the
expectation was that a weaker model would show at least some baseline
failures the skill could then visibly fix. That did not happen here.

A few things are worth noting about *how* Haiku's baseline held up, since
they're more informative than the bare pass count:

- **Haiku's with-skill and baseline responses were both noticeably
  shorter and less exhaustively hedged than Sonnet 5's**, but the core
  judgment calls (reject the plausible wrong answer, ask for the missing
  evidence, refuse to close prematurely) were intact in both conditions
  across all 12 scenarios.
- **Scenario A and E baseline responses skipped tool use** (no attempt to
  search the repo for the referenced files) where the with-skill versions
  in some cases did use tools (see I, L). This is a possible signal that
  the skill nudges toward more thorough investigation *behavior*, even
  where it doesn't change the final verdict — but with only one data point
  per condition per scenario, this isn't a confirmed pattern, just an
  observation worth checking in a larger sample.
- Scenario E's "ask for the file path" response in both conditions is a
  property of this test environment (no real button component exists to
  edit) rather than a skill effect — worth noting so it isn't
  misread as evidence of anything.

## Recommendation

Across four independent runs now (Sonnet 5 × 3 rounds, Haiku 4.5 × 1
round; 36 total scenario executions, all with-skill/baseline pairs), no
scenario in `tests/scenarios.md` has shown a baseline failure that the
skill then corrects. The "test a weaker model" hypothesis from the prior
run's recommendation did not pan out — Haiku 4.5's baseline judgment on
these specific constructed scenarios is essentially as robust as Sonnet
5's.

This changes the recommended next step. Rather than continuing to test
progressively weaker models or more adversarial scenario construction
(which has now been tried twice without success), the more promising
directions are:

1. **Move to the structure/quality rubric mentioned in the prior run's
   recommendation.** Since final-verdict pass/fail isn't discriminating
   at any tested model tier, the skill's demonstrable value — if it has
   one measurable in this kind of eval — is in response structure
   (explicit evidence labeling, named falsification steps, tool-use
   thoroughness) rather than the conclusion reached. This is the next
   planned step per the user's request.
2. **Consider that these scenarios may simply not be where this skill's
   value shows up for current-generation models.** All three Claude
   models/tiers tested so far bring enough default epistemic caution to
   pass hand-constructed scenarios like these. The skill's real value
   may be more visible in *ambient* behavior over a long, unstructured
   task (where there's no test-shaped prompt cueing carefulness) than in
   a scenario explicitly designed to test for a specific failure mode —
   which is a harder thing to eval but worth keeping in mind when
   interpreting "8/8" or "12/12 pass" as a clean result rather than a
   ceiling effect in this eval design.

All scenarios remain valid regression guards regardless of this finding.
