# Behavioral Test Run — 2026-08-21

Method: for each scenario, two independent agent runs were executed from the
same prompt — one instructed to follow `SKILL.md` (with-skill), one with no
skill framework (baseline). Pass/fail criteria are from
[`tests/scenarios.md`](../scenarios.md). Model: Claude Sonnet 5.

5 of 8 scenarios were run in this pass (A, B, D, E, G). C, F, H were not yet
executed — see Follow-ups.

## Interpretation

At this model tier (Sonnet 5), baseline behavior on these 5 scenarios was
already close to the skill's target behavior — both conditions passed all 5.
This means these particular scenarios are currently **non-discriminating**:
they don't show a stark behavioral gap baseline vs. with-skill, so they're
weak evidence for "the skill changes behavior" on their own.

What the skill visibly added on the *with-skill* side, consistently:
- explicit FACT / ASSUMPTION / UNKNOWN / CLAIM labeling
- explicit VERIFIED / STRONGLY SUPPORTED / INFERRED classification
- named falsification attempts on the leading hypothesis
- an explicit "why might a reasonable engineer have written this" framing before touching legacy code

These are qualitative, structural differences rather than differences in the
final recommendation. The scenarios most likely to show a *harder* pass/fail
split are the ones not yet run — C (confirmation bias / contradictory
evidence) and F (speculative refactor opportunism) in particular are designed
to catch a baseline model actively ignoring or downplaying inconvenient
evidence, which is a more subtle failure mode than "state the wrong root
cause."
