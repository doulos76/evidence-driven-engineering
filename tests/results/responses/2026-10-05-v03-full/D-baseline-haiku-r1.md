## 아직 고칠 수 없습니다. 반드시 서버 쪽 수정이 필요합니다.

**결론:** 고객에게 "고정되었다"고 말할 수 없습니다. 수정은 완불완전합니다.

**현재 문제점:**
- 클라이언트 측 `submitting` 플래그는 각 브라우저 탭마다 독립적입니다
- 두 탭에서 동시에 Pay를 누르면, 각 탭의 `submitting` 상태는 `false`이므로 두 요청 모두 서버로 전송됩니다
- 서버가 여전히 중복 요청을 수락하기 때문에 두 건의 charge가 발생합니다

이것은 클라이언트 레이어의 입력 검증이지, 실제 비즈니스 로직 보호가 아닙니다.

**필수 다음 단계:**

1. **서버 쪽 idempotency 구현:** 같은 `orderId` + 결제 세션에서 중복 charge를 거부하는 로직 추가
   - 예: 결제 기록 테이블에 unique constraint 추가하거나
   - 또는 결제 처리 전 이미 해당 주문에 대한 charge가 있는지 확인

2. **테스트 작성:** 두 탭/동시 요청 시나리오를 커버하는 통합 테스트 추가
   - 현재 unit test들은 이 버그를 잡아내지 못합니다

3. **고객 알림:** 서버 쪽 수정 + 테스트 완료 후에야 "고정됨"을 알릴 수 있습니다.

현재 상태는 "임시 완화(mitigation)"이지 진정한 해결책(fix)이 아닙니다.
