## 삭제 가능 여부: 조건부 삭제 권장

**결론**: 이 래퍼는 삭제할 수 있지만, 실행 전에 3가지 핵심 검증이 필요합니다.

**근거:**
- ✓ 최신 smoke 테스트는 API 34에서 성공하고, "modern TLS support" 의존성 업그레이드가 있음
- ✓ 코드 자체는 API 21–22 범위의 명시적 설정일 뿐, 제거해도 더 최신 안드로이드는 네이티브 TLS 1.2를 지원함
- ✗ 그러나 **API 21–22 기기에서 최신 smoke 테스트 결과가 없고**, **호출 감시가 없어서** 실제 영향 범위를 알 수 없음

---

## 삭제 전 필요한 구체적 검증

### 1. 호출 감시 (Caller Audit)
- `createConnection()` 메서드를 호출하는 모든 경로 확인
- 로그인과 백그라운드 동기화 외에 다른 사용처가 있는지 확인
- 각 호출처에서 실제로 필요한지 여부 판단

### 2. "Modern TLS Support" 의존성 검증
- 의존성 업그레이드 노트에서 명시한 "modern TLS support"가 정확히 무엇인지 확인
- 해당 기능이 API 21–22 기기에서도 TLS 1.2를 자동으로 활성화하는지 테스트
- 이 래퍼 제거 시 안드로이드 기본 SSLSocket 동작 재확인

### 3. API 21–22 기기 대상 smoke 테스트
- 최신 smoke 테스트에서 API 21–22 결과가 없는 이유 확인 (테스트 커버리지 문제인지, 기기 부재인지)
- 필요시 래퍼를 제거한 빌드로 API 21–22 기기(또는 에뮬레이터)에서 로그인/동기화 재테스트
- TLS endpoint policy가 실제로 API 21–22와 호환되는지 엔드포인트 검증

### 4. 운영 중 기기 분포 확인
- 제품 분석에서 API 21–22 기기의 활성 사용자 비율 조회
- 비율이 무시할 수 있을 정도인지 확인

---

## 최종 권장사항

**단계별:**
1. 위 검증 4가지 완료 후
2. 운영 기기의 API 21–22 비율이 < 1% (또는 조직의 최소 지원 요건)이고
3. Modern TLS 의존성이 API 21–22를 커버한다면
4. **삭제 진행 + 회귀 테스트**

만약 API 21–22 기기가 여전히 소수 사용자를 서빙한다면, 기술적 부채가 아닌 **호환성 유지 코드**이므로, 대신 다음과 같이 개선:
- 주석에 "SDK 21-22 호환성 유지, 의존성 업그레이드 후 재평가" 추가
- 의존성 업그레이드 추적 티켓 생성 (시 버전 업데이트 등으로 제거 가능해질 때)
